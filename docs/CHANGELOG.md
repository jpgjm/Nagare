# 変更履歴

## 1.0.4 (5)

アプリのコードは 1.0.3 と同じ。ビルド用ワークフローを rev9 → rev10 に更新。

- ビルドより前のステップ（プロジェクト生成・スキーム解決など）で失敗しても、`…_xcodebuild-log` の ZIP が上がるようにした
  - ログファイルを最初のステップで作り、各ステップの出力を追記する。各ステップの頭に `===== [ステップ名] 時刻 =====` が入るので、ログの末尾を見れば止まった場所が分かる
  - ログの表示とアップロードをジョブの最後へ移した（.app 検証・署名・IPA 化で落ちた場合も残る）
- `xcodebuild -list` のエラー出力を捨てないようにした（rev9 は `2>/dev/null` で捨てていたため、1.0.3 のビルドは失敗理由が残らなかった）
- Swift Package の解決を独立させ、失敗したら 3 回まで再試行するようにした


## 1.0.3 (4)

v1.0.2 の実機ログで、**拡張機能（Nyaa）→ トレント → mpv 再生が通しで動く**ことを確認（H.264 720p / 480p、videotoolbox、シーク・字幕切替も動作）。残った問題の修正。

- **Nyaa の検索語が効かず、無関係な人気トレントが並ぶ問題の対策**
  - ログで確認できたこと: 送信 URL はブラウザ（WHATWG）の形で、こちらで同じ URL・同じ User-Agent を HTTP/1.1・HTTP/2 で送ると正しい結果（single 60 件 / batch 27 件）が返る。アプリでは batch が検索語なしの一覧（75 件）、single が 28 件になっていた
  - 両者の違いは URL を iOS の通信層（URL / URLSession）に渡す部分だけ。この URL には RFC 3986 で使えない `|` が生のまま入っており、iOS の `URL(string:)` はこれを寛容に受け入れるため、送信時の扱いが不定になる
  - 対策: 使えない文字（`|` など）を UTF-8 でパーセントエンコードした厳密な URL にしてから送る（`%7C` の形でサーバが同じ結果を返すことは確認済み）。変換したときはログに出す
  - あわせて拡張の通信では URL キャッシュを使わないようにした
- 通信 URL のログを 4000 文字まで残すようにした（1.0.2 は 1500 文字で切れていた）

検証: 上書きインストールで確認できます。


## 1.0.2 (3)

v1.0.1 の実機ログ（iPad 第9世代 / iPadOS 26.6.2）で見つかった問題の修正。

- **再生が始まった直後にプレイヤーが止まる問題を修正**
  - 原因: 準備画面（シート）が閉じ切る前に全画面プレイヤーが出たため表示が作り直され、そのとき呼ばれた onDisappear で mpv を破棄していた（ログ: 「再生開始 → プレイヤーを閉じました → 再生開始 → mpv 破棄しました」が 0.1 秒以内に並ぶ）
  - mpv の破棄は「閉じる」操作とビューの解体時だけにした
  - 全画面はシートの onDismiss を待ってから出すようにし、同じ再生要求の重複も無視するようにした
- 拡張の通信で送った URL をログに残すようにした（key / token などを含むパラメータは伏せる）。Nyaa の検索結果に無関係な作品が並んだ件の調査用
- 検索結果の内訳（single / batch / movie の件数）と先頭の結果をログに出すようにした
- mpv に存在しないオプション（ytdl）の指定を削除

検証: 上書きインストールで確認できます。

## 1.0.1 (2)

拡張機能で見つけたトレントを再生できることを最優先に、[Spithskia/Shiru-Extensions](https://github.com/Spithskia/Shiru-Extensions) の 7 件の拡張に合わせて直しました。

- 拡張の `fetch` がすべて失敗しうる不具合を修正（日本語の statusText を `Response` が受け付けないため）
- 応答ヘッダに不正な文字があっても例外にしないように修正
- magnet に Shiru と同じ既定トラッカーを付加（TsukiHime のトラッカー無し magnet、SeaDex の infohash のみのリンク向け）
- infohash だけのリンクを magnet として開けるように修正
- IndexedDB が使えない環境ではメモリ上の代替に切り替え（nekoBT / TsukiHime の読み込み失敗を防ぐ）
- esm.sh から Safari 向けのコードを取得するように変更
- 拡張 1 件あたりの検索の待ち時間を 60 秒 → 120 秒に（TsukiHime は最大 6 回再試行する）
- バッチの中から話を選ぶ判定を強化（強い一致を優先、特典類を除外、通し番号でも試す）
- リポジトリの「すべて追加」ボタン、SeaDex の「ベスト」表示を追加

検証: 上書きインストールで確認できます（installd がキャッシュする Info.plist 項目は変えていません）。
