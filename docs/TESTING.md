# 動作確認の手順

問題が起きたときに「どこまでは動いているか」を切り分けられるよう、仕組みが単純なものから順に確認します。
各段階で期待どおりにならなかったら、**ログタブ → 右上メニュー → 表示中のログを書き出す** で書き出したファイルを添付してください。

## 0. 起動

ログタブを開き、先頭付近に次のような行があること。

```
[INFO] [app] 起動: Nagare 1.0.0 (1) / BundleID: com.anony.nagare.XXXXXXXXXX / …
[INFO] [diag] OpenSSL: OpenSSL 3.x.x … / SSL_CTX_new → …
[INFO] [ext-host] 拡張ランタイムの準備ができました
```

## 1. トレント → ストリーミング → mpv（拡張機能を使わない）

**設定 → 動作確認 → テスト再生（Sintel / CC BY 3.0）** を押します。
Blender Foundation の短編映画 Sintel（約 130MB、自由に再配布できる公開トレント）を使います。

期待する結果:

1. 「再生の準備」画面で「メタデータ取得中」→ 自動でプレイヤーが開く
2. 映像と音声が出る。タップで操作パネルが出る
3. シーク（±10 秒、スライダー）で少し待ったあと再生が続く
4. ログに次のような行が出る
   - `[torrent] メタデータ: Sintel（… ファイル …）`
   - `[torrent] 再生ファイル: Sintel/Sintel.mp4 …`
   - `[mpv] 初期化完了: mpv …`
   - `[player] 映像: <幅>x<高さ> … hwdec=videotoolbox`（hwdec が `no` ならソフトウェアデコード）

ここで失敗する場合、原因は拡張機能ではなくトレント・サーバ・プレイヤーのいずれかです。

## 2. 拡張機能の読み込み → 検索結果の表示

**拡張機能タブ → 動作確認用のダミー拡張を追加** → 一覧に出た「Dummy Extension」を有効にします。

- 状態が「有効」（緑）になること
- 検索タブで任意の作品（例: `Frieren`）→ 話数を選ぶ → 「拡張機能でトレントを探す」
- 「Dummy Extension」から数件の結果が返ること

ダミー拡張は**架空の**トレントを返すので、開いてもメタデータは取得できません（期待どおり）。
ここまで動けば、マニフェストの取得・コードの読み込み（esm.sh 経由）・WKWebView 上での実行・ネイティブ fetch の中継が動いています。

## 3. 実際の拡張機能（Spithskia/Shiru-Extensions）

1. 拡張機能タブの入力欄に `gh:Spithskia/Shiru-Extensions` を入れて「追加」
2. 「リポジトリ: gh:Spithskia/Shiru-Extensions」の欄で **未追加の 4 件をすべて追加**
3. インストール済みに次の 7 件が並ぶので、使うものを有効にする（緑の「有効」になること）

| 拡張 | 返すリンク | 備考 |
|---|---|---|
| SeaDex | infohash のみ | 高品質なリリースのまとめ。ほぼ全話入りのバッチ |
| Anime Tosho (New) | magnet | AniDB の話 ID で検索するので精度が高い |
| Anime Tosho (Archive) | magnet | 2026 年 10 月に完全終了予定（非推奨） |
| Nyaa | magnet（トラッカー 1 件） | 題名での検索。別シーズンの同じ話数も混ざる |
| Sukebei | magnet | 成人向け。「設定 → 成人向け…」が OFF なら検索されない |
| nekoBT | magnet | 設定で字幕・音声の言語を絞れる（未選択なら絞らない） |
| TsukiHime | magnet（**トラッカー無し**） | シーダー数は常に 0 と表示される |

4. 検索タブ → 作品 → 話数 → 「拡張機能でトレントを探す」
   - 拡張ごとに件数が出ること（「エラー」「スキップ」なら、その下の文とログの `[ext]` `[ext-fetch]` を確認）
5. 結果を選ぶ → 「再生の準備」→ 自動で再生が始まること
   - バッチ（全話入り）を選んだときは、ファイル名から話を自動で選ぶ。決まらないときはファイル一覧が出るので選ぶ
   - ログの `[torrent] リンク: magnet:?xt=…（トラッカー N 件）` で、付加後のトラッカー数を確認できる

**おすすめの確認順**: トラッカー付きの magnet を返す Anime Tosho (New) か Nyaa で 1 話ものを再生 → SeaDex / nekoBT のバッチ → TsukiHime。
前のものが再生できて後のものだけ失敗するなら、原因はリンクの形（infohash のみ・トラッカー無し）かバッチ内の話の選択に絞れます。

## 4. バックグラウンド

1. 再生中にホーム画面へ戻る → 音声が続くこと
2. アプリに戻る → 映像が戻ること（ログに `フォアグラウンドへ: 映像出力を再開`）
3. 一時停止した状態でホームへ戻り、しばらくしてから戻ってもダウンロードが続いていること（トレントタブの進捗）

## うまくいかないとき

| 症状 | 見る場所 |
|---|---|
| 起動直後に落ちる | Actions のビルドログの `[Nagare] OK: OpenSSL.framework …` の行 |
| メタデータ取得中のまま | ログの `[torrent]` の peers 数。0 のままならネットワーク／トラッカー側 |
| 読み込み中のまま再生されない | ログの `[stream] ピース … を待っています`、`[server]` の行 |
| 拡張が「エラー」 | 拡張機能の詳細画面のエラー文と、ログの `[ext]` `[ext-resolve]` `[ext-fetch]` |
| 映像が出ず音だけ | 設定 → 診断 → mpv の詳細ログ を ON にして再現し、`[mpv/vo]` の行 |
